# Documentation Archive

Archived docs are historical execution evidence. They preserve completed checkpoint artifacts, superseded plans, audit outputs, remediation summaries, baseline snapshots, and historical release or presentation evidence.

Active/current reviewer documentation lives in the main docs lanes and root reviewer files, including `README.md`, `REVIEWERS.md`, `CHANGELOG.md`, `docs/ai-index.md`, `docs/repo-map.json`, current lane README files, current canonical product/security/architecture/operations docs, current release workflow/checklist docs, current taskboard/backlog records, and current reviewer walkthroughs under `review/`.

Archived docs may describe earlier branch states, older paths, or decisions that were later superseded. They should not be treated as the current product behavior, release state, reviewer contract, engineering standard, or deployment contract unless a current active doc explicitly points to them for historical context.

The archive is retained for traceability, auditability, and delivery evidence.

## Structure

- `v1/checkpoints/`: frozen `V1` checkpoint plan, workflow, status, and PR evidence.
- `v1/release-evidence/`: historical `V1` release and deployment setup evidence.
- `v1-1/baseline-and-review-infra/`: frozen `v1.1.0` baseline and reviewer-infrastructure evidence.
- `v1-1/engineering-security-architecture/`: completed `v1.1` engineering/security/architecture review evidence.
- `v1-1/remediation/`: completed remediation inventories, summaries, and acceptance-review evidence.
- `presentation-history/`: superseded or historical presentation/design artifacts.
